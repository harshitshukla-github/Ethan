# Task REST API

A simple Node.js + Express project for learning how REST APIs work. It uses ES modules (`.mjs`), separates routes from controllers and storage, validates requests, and returns JSON errors.

**Storage is in memory. Restarting the server restores the original two sample tasks.** This version is a local learning project with no login or database.

## Requirements

- Node.js 22 or newer (npm comes with Node.js).
- A terminal and a code editor.

Check your installation:

```bash
node --version
npm --version
```

## Start the project

1. Extract the ZIP.
2. Open a terminal inside the extracted `task-api` folder (the folder containing `package.json`).
3. Run:

```bash
npm install
npm start
```

Open <http://localhost:3000/tasks> in your browser. Keep the terminal running while making requests. Press **Ctrl+C** to stop the server.

For automatic restarts when you edit source files:

```bash
npm run dev
```

Each automatic restart also resets the in-memory data. Run either `npm start` or `npm run dev`, not both on the same port.

The project includes a lockfile. Use `npm ci` instead of `npm install` when you want to install exactly the recorded dependency versions. The ZIP excludes `node_modules`; npm downloads dependencies during setup.

## Project files

| Path | Purpose |
| --- | --- |
| `src/server.mjs` | Starts the HTTP server and reads its port/host configuration. |
| `src/app.mjs` | Creates the Express app and connects middleware and routes. |
| `src/routes/task.routes.mjs` | Maps HTTP methods and URLs to controllers. |
| `src/controllers/task.controller.mjs` | Handles requests and sends responses. |
| `src/store/task.store.mjs` | Stores and modifies the task array in memory. |
| `src/middleware/validation.mjs` | Checks task IDs, JSON content type, and titles. |
| `src/middleware/errors.mjs` | Returns consistent JSON errors. |
| `tests/api.test.mjs` | Exercises the API through real HTTP requests. |
| `requests.http` | Ready-to-send example requests. |
| `package.json` | Project settings, scripts, and dependencies. |
| `package-lock.json` | Exact dependency versions for repeatable installation. |

A request passes through JSON parsing, a route, validation, and a controller. The controller uses the store and sends the HTTP response. For a future SQLite version, the store is the main module to replace.

## Endpoints

Base URL: `http://localhost:3000`

| Method | Path | Purpose | Success status |
| --- | --- | --- | --- |
| GET | `/` | API overview | 200 |
| GET | `/health` | Server health | 200 |
| GET | `/tasks` | All tasks | 200 |
| GET | `/tasks/:id` | One task | 200 |
| POST | `/tasks` | Create a task | 201 |
| PATCH | `/tasks/:id` | Change a task title | 200 |
| DELETE | `/tasks/:id` | Delete a task | 204 |

### Read tasks in a browser

Open <http://localhost:3000/tasks> to see:

```json
[
  { "id": 1, "title": "Learn Node.js" },
  { "id": 2, "title": "Build a REST API" }
]
```

Open <http://localhost:3000/tasks/1> to see a single task.

### Create a task with Postman or Thunder Client

1. Select **POST**.
2. Enter `http://localhost:3000/tasks`.
3. Set the request body format to **JSON** (Postman: **Body > raw > JSON**).
4. Ensure the `Content-Type` header is `application/json`.
5. Send this body:

```json
{
  "title": "Learn Express"
}
```

On a fresh server, the response is **201 Created**:

```json
{
  "id": 3,
  "title": "Learn Express"
}
```

The `Location` response header is `/tasks/3`. Use the actual returned ID for later requests.

### Update a task

Send **PATCH** to `http://localhost:3000/tasks/3` using a JSON body:

```json
{
  "title": "Practice Express"
}
```

The response is **200 OK** with the updated task.

### Delete a task

Send **DELETE** to `http://localhost:3000/tasks/3` with no body. A successful response is **204 No Content**, so its body is empty. Reading the same ID afterward returns **404 Not Found**.

Typing a URL into your browser's address bar sends GET; use an API client for POST, PATCH, and DELETE. The included `requests.http` file can also be used with the optional VS Code REST Client extension. Send its examples in order after starting a fresh server.

## Validation and errors

- IDs must be positive safe integers, such as `1` or `3`.
- POST and PATCH accept only a JSON object containing `title`.
- Titles must be strings with 1 to 200 JavaScript string units after trimming whitespace (`String.length`). Some emoji count as two units.
- IDs are generated by the server; do not include an `id` field in a request body.
- The JSON request size limit is 16 KB.
- Titles are trimmed before storage.

Errors have this shape:

```json
{
  "message": "Task not found"
}
```

| Status | Meaning |
| --- | --- |
| 400 | Invalid ID, invalid title/body, unexpected fields, or malformed JSON. |
| 404 | Task or endpoint not found. |
| 413 | Request body exceeds the size limit. |
| 415 | Unsupported content type or encoding. |
| 500 | Unexpected server error. |

## Run the tests

```bash
npm test
```

The tests use Node.js's built-in test runner and `fetch`, start their own servers on free ports, and do not require a separately running API. They check the full create/read/update/delete flow, generated IDs, validation, JSON parsing, content types, size limits, and missing resources.

## Configuration

The default address is `127.0.0.1:3000`. The server reads `PORT` and `HOST` from the process environment. No `.env` file is needed or automatically loaded.

If port 3000 is already in use, stop the other server or choose another port.

Windows PowerShell:

```powershell
$env:PORT = "4000"
npm start
```

Windows Command Prompt:

```bat
set PORT=4000
npm start
```

macOS/Linux:

```bash
PORT=4000 npm start
```

Then use `http://localhost:4000/tasks`. Update the base URL in `requests.http` if you use it. `HOST` defaults to the loopback address for local use; set it to `0.0.0.0` only when you intend to accept connections from other devices or a hosting platform.

## Troubleshooting

- **`node` is not recognized:** install Node.js, reopen your terminal, and check `node --version`.
- **Cannot find package `express`:** run `npm install` from the folder containing `package.json`.
- **Port already in use:** stop your earlier server with Ctrl+C or change `PORT`.
- **Connection refused:** start the server and use the port displayed in its terminal.
- **415 response:** select a JSON body and send `Content-Type: application/json`.
- **Tasks disappeared:** restarting the server resets the in-memory store by design.
